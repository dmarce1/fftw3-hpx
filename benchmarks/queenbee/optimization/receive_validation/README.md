# Local receive-prototype validation

Both exact [frozen receive prototypes](../receive_prototypes/README.md) passed
the local correctness checks below on 2026-10-23 UTC. These records establish
local compilation and correctness, not QueenBee transport performance or a
guaranteed direct-receive hit rate. [SUMMARY.json](SUMMARY.json) indexes the
original machine-readable results.

| Validation layer | Direct receive | Pooled receive |
| --- | --- | --- |
| Double, single, and long-double standard matrices | PASS, 15 matrix invocations | PASS, 15 matrix invocations |
| Assertion-enabled communication, 1 locality × 2 workers and 3 × 2, in each precision | PASS, 6 runs | PASS, 6 runs |
| Initial double-precision communication and unchanged N=64 matched driver, 4 localities × 2 workers | PASS | PASS |
| Deterministic HPX archive/ownership tests, double configuration | PASS, 6 groups | PASS, 4 groups |

The all-precision phase contains **30 standard matrix invocations and 12
communication invocations**. It reproduces the `hpx/Makefile.am` `check-local`
transform commands: `tests/check.pl --verbose --random --maxsize=10000 -c=10
--mpi` at 1×1, 2×1, 3×1, and 4×1, followed by 3×2 with `--nthreads=2`.
Each precision also runs the standard 3×2 communication check and an additional
1×2 singleton communication check. Random cases were generated independently;
the logs retain every realized benchmark command. These invocation counts are
not counts of individual transform variations generated by `check.pl`.

All distributed local runs used **TCP only between processes on this one
workstation**. No TCP traffic between servers and no QueenBee access were part
of this validation. The local runner clears inherited remote launch settings
and explicitly disables the MPI parcelport. The unchanged matched driver used
recorded command-line overrides to select local TCP. Cluster experiment
results belong to separate evidence and use the MPI parcelport with TCP
disabled. Runtime matrices were serialized, with at most six HPX workers;
the earlier N=64 check used eight. At most two compilers ran concurrently.

Only the prototype bridge was compiled for each precision. Existing matching
benchmark C/C++ objects and serial, thread, and `libbench2` archives were reused.
Each copied HPX archive has the same 32 members, with only `hpx-comm.o` changed;
the other 31 members are byte-identical. Original inputs, prototype sources,
and resulting outputs were hash-checked. Communication checks were compiled
with `-UNDEBUG`. Frozen prototypes and the matched benchmark driver were not
modified during testing.

## Evidence layout

- [precision_validation/SUMMARY.json](precision_validation/SUMMARY.json): all
  six prototype/precision combinations, exact commands, statuses, and counts.
  Their subdirectories preserve build/test logs, result tables, command traces,
  archive-member hashes, and original input/output manifests.
- [local_validation/SUMMARY.json](local_validation/SUMMARY.json): the earlier
  double-precision checks, including the unchanged N=64 driver with two warmups
  and seven samples. Numerical checks and plans passed for both prototypes.
  Timings are retained as raw correctness-run output, not performance evidence.
- [prototype_units](prototype_units/README.md): exact deterministic test
  sources, shared archive helper, original `run_one.sh`, and results. The
  [unit summary](prototype_units/results/summary.json) records six direct and
  four pooled check groups. These ordinary-main programs use real HPX
  serialization archives without starting a distributed runtime. The direct
  zero-copy test verifies destination selection and simulates the transport
  fill; it does not perform an MPI transfer. The pool tests cover last-owner
  release, exact-size reuse, cache retention, and cleanup/epoch isolation.
- [helpers](helpers): the exact local and all-precision validation scripts.
  [environment](environment) preserves the original dependency environment and
  three precision configuration headers; [inputs](inputs) preserves the
  communication check, local runner, matched driver, and `check.pl` used here.
- [SOURCE_MAP.json](SOURCE_MAP.json): original-to-published paths and SHA-256
  hashes for every unchanged copied evidence file. `SHA256SUMS` covers the
  publication package itself, including this documentation.

Two unsuccessful preparation attempts are intentionally retained. The first
local direct-receive launch could not create TCP sockets inside the restricted
sandbox; the same local-only tests subsequently passed with socket access.
The first pooled unit-test compilation found a missing closing brace in the
test source; that test-source error was fixed before the successful build and
run. Neither event required a frozen prototype change. Their diagnostic logs
are named `*_sandbox_network_denied.log` and `build_attempt1.log`.

## Preserving and replaying the original layout

Evidence files are copied byte for byte, so absolute paths and build-directory
references in the original logs, commands, summaries, scripts, and unit includes
are intentionally unchanged. They describe the recorded workstation, not
portable installed paths. Historical `input.sha256` and `output.sha256` files
include objects and executables deliberately omitted from publication. Verify
the distributed text/source package with `sha256sum -c SHA256SUMS` from this
directory, rather than expecting those historical manifests to find omitted
binaries.

To replay the helpers, first prepare a disposable checkout with the matching
local HPX/dependency environment and double, single, and long-double FFTW build
trees. See the repository [HPX build instructions](../../../../hpx/README.md).
Then restore this source-only layout beneath that checkout's `build/qb_optimize`:

| Published content | Original relative location beneath `build/qb_optimize` |
| --- | --- |
| [direct frozen source](../receive_prototypes/direct_receive/hpx-comm.cpp) | `direct_receive/hpx-comm.cpp` |
| [pooled frozen source](../receive_prototypes/pooled_receive/hpx-comm.cpp) | `pooled_receive/hpx-comm.cpp` |
| `prototype_units/*_units.cpp`, `archive_helpers.hpp`, `run_one.sh` | Same filenames under `prototype_units/` |
| `helpers/validate_local_prototype.sh` | `validate_local_prototype.sh` |
| `helpers/validate_precision_matrix.sh` | `validate_precision_matrix.sh` |

The unit sources deliberately retain their tested `../direct_receive/...` and
`../pooled_receive/...` includes. This restored layout resolves those includes
to the frozen sources without editing them. The helpers expect a locally
configured `build/hpx_env.sh`; the archived copy records the environment used
here. Run them only in the disposable layout, so the published evidence is not
overwritten. For each prototype, the original sequence is:

```sh
bash build/qb_optimize/prototype_units/run_one.sh build direct_receive
bash build/qb_optimize/prototype_units/run_one.sh test direct_receive
bash build/qb_optimize/validate_local_prototype.sh build direct_receive
bash build/qb_optimize/validate_local_prototype.sh test direct_receive
for precision in double single long_double; do
    bash build/qb_optimize/validate_precision_matrix.sh build direct_receive "$precision"
    bash build/qb_optimize/validate_precision_matrix.sh test direct_receive "$precision"
done
```

Use `pooled_receive` for the other prototype. The double-precision matrix helper
reuses the archive from the preceding initial local build. Socket access is
required for the distributed local checks. Keep every locality on the same
host and serialize runtime launches as in the recorded run.
